# Documentation for Developers (API)
Extension: `eunaumtenhoid/payments`

This extension acts as a **Central Payments Engine** for phpBB. It centralizes API keys and communication logic with banks/gateways.

If you are building an extension that needs to charge the user (e.g., Donations, Marketplace, VIP/Credits System), **you do not need to implement gateway logic from scratch**. Simply send a data payload to this extension, and it will return a ready-to-use payment link for the user.

---

## 1. Dependency Injection

To use the payments API, your extension needs to inject the `@eunaumtenhoid.payments.manager` service into your controller.

In the `config/services.yml` file of **YOUR** extension, add:

```yaml
services:
    your_vendor.your_extension.controller:
        class: your_vendor\your_extension\controller\main
        arguments:
            - '@eunaumtenhoid.payments.manager'
```

In the constructor of your extension's class:

```php
protected $payment_manager;

public function __construct(\eunaumtenhoid\payments\payment\manager $payment_manager)
{
    $this->payment_manager = $payment_manager;
}
```

---

## 2. Create Payment

When the user clicks "Buy", call the `create_payment` method passing the desired gateway name.

### Supported Gateways
* `mercadopago` (Pix, Boleto, Credit Card)
* `stripe` (Credit Card, Apple/Google Pay)
* `paypal` (Balance, Credit Card)
* `coinbase` (Crypto - USDC/Base)
* `btcpay` (Bitcoin Natively)
* `coinpayments` (Altcoins)

### Usage Example:

```php
try {
    // Returns an Array with checkout data
    $checkout_data = $this->payment_manager->create_payment([
        'provider'    => 'mercadopago', // Which gateway to use
        'amount'      => 5000,          // Amount in cents (5000 = $50.00)
        'currency'    => 'BRL',         // BRL, USD, EUR
        'description' => $this->language->lang('YOUR_EXT_PURCHASE_DESCRIPTION'),
        'return_url'  => $this->controller_helper->route('your_vendor_your_ext_success', [], true) // Generate the absolute URL for your route
    ]);
    
    $transaction_id = $checkout_data['transaction_id']; // Save this in your extension's database!
    $checkout_url = $checkout_data['url'];             // Redirect the user here or open in an iframe
    
    // Redirect the user to payment
    return new \Symfony\Component\HttpFoundation\RedirectResponse($checkout_url);

} catch (\Exception $e) {
    echo $this->language->lang('YOUR_EXT_PAYMENT_ERROR') . ': ' . $e->getMessage();
}
```

---

## 3. Verify Payment

After the user returns to your forum, you need to verify if the payment was actually approved before granting the benefit (VIP, Credits, etc).

Take the `$transaction_id` you saved in the previous step and call the `verify_payment` method.

```php
try {
    $result = $this->payment_manager->verify_payment('mercadopago', $saved_transaction_id);

    if ($result['status'] === 'paid') {
        // Success! Payment received. Grant the user's VIP here.
        echo $this->language->lang('YOUR_EXT_PAYMENT_APPROVED');
    } elseif ($result['status'] === 'pending') {
        echo $this->language->lang('YOUR_EXT_PAYMENT_PENDING');
    } else {
        echo $this->language->lang('YOUR_EXT_PAYMENT_FAILED');
    }

} catch (\Exception $e) {
    echo $this->language->lang('YOUR_EXT_VERIFICATION_ERROR') . ': ' . $e->getMessage();
}
```

---

## Additional Tips

* **Modals and Iframes:** URLs generated by crypto gateways (`btcpay`, `coinbase`) work very well inside iframes (floating windows). If your extension wants a modern experience, insert the returned URL into an HTML modal instead of redirecting the page.
* **Currency:** The API accepts standard fiat codes (BRL, USD). The crypto provider handles the conversion of the requested fiat amount (e.g. $50) to the corresponding digital currency fraction at the time of opening the invoice for the user.
